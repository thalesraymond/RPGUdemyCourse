# Domain Docs

## Layout

This is a single-context repository:

- `GLOSSARY.md` at the repository root.
- Architecture decision records under `docs/adr/`.

## Before exploring

Read the glossary and ADRs relevant to the work.

If these documents do not exist, proceed silently. Create them
lazily through domain-modeling when terms or decisions are resolved.

## Vocabulary

Use glossary terms in issues, proposals, tests, and other output.
If a needed concept is missing, reconsider the term or note the gap
for domain-modeling.

## ADR conflicts

Explicitly flag proposals that contradict an existing ADR,
identifying the ADR and why its decision deserves reconsideration.
